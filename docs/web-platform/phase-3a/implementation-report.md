## Final recovery: audit ownership and process decision

### Root cause and reproduction

Installed addon-a11y 10.6.3 starts its automatic audit from the story afterEach lifecycle and lazily imports axe-core. Its internal queue serializes only addon-owned runs. Our helper independently injected axe.source and later evaluated window.axe.run. Importing axe publishes a mutable window.axe global; when the lazy addon import occurs between those helper steps, the helper can call the addon's currently running instance. Element visibility is not proof that the addon's lifecycle audit finished.

This is page-local concurrency, despite the existing single Playwright worker. Each test has an isolated context, but automatic and custom audits target the same iframe document. The viewport loop performs fresh navigations; a newly rendered document can reach visible controls before its automatic audit completes. No evidence indicated cross-context state leakage or a need to serialize unrelated tests.
