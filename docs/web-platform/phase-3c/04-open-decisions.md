## Architectural consultation and ADR impact

Read-only architect consultation in 3C.0 confirmed minimal Profile module, app-owned routes/cookies/metadata, current bootstrap retained in Identity, existing edit SQL, future username projection and private avatar saga. The architect verified the shared profiles-row lock, independent revisions, null-only avatar contract and restricted reader's lack of avatar-path privilege. No tests/network/scripts were run by the specialist; execution results belong to the main session.

ADR impact **NONE for 3C.0 documentation**. The proposed implementation is compatible with ADR-0002/0003 and accepted Phase 0 boundaries. At implementation planning, record a **NEW** ADR if the new Profile/storage public ownership/capability contract is adopted; no superseding ADR is currently justified. Username canonical URLs refine an old Phase 0 proposal and do not supersede accepted UUID identity. Do not create a new FSD policy or migrate existing Auth/UI structure.

## Readiness

### Phase 3C.1 decision acceptance — 2026-10-27

The subsequent explicit implementation instruction accepts D-01–D-03 recommended defaults and D-06 immediate username reuse for **3C.1 only**. A released handle becomes immediately available, with a visible owner warning and no old-name redirect; UUID identity stays stable. The original table and planning review above remain the historical decision context. D-04/D-05 and D-07–D-10 remain deferred to their applicable later scope. Current implementation/evidence status is recorded separately in the Phase 3C.1 report and `phase-three-c-profiles-privacy` change; the Phase 3C.0 report remains historical.

The audit and proposed design are sufficient for a concrete product/architecture decision. They are **not permission to implement 3C.1**. D-01–D-03, D-06 and a separate implementation authorization are prerequisites; later-stage gates may remain deferred until their stage, but must be closed before dependent code/spec commitments. Canonical OpenSpec/BDD/TDD scaffolding and baseline are future work after that authorization, not missing historical evidence to invent now.

Remote deployment state, live Google login, external SMTP, remote CI, production CDN behavior, decoder runtime support and Storage acceptance are unverified. The final [planning report](PHASE-3C-PLANNING-REPORT.md) records actual local validation and independent review limitations.
