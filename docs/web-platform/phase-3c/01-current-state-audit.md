`app_private.touch_revision` increments revision and updates time on every table update. Revisions are PostgreSQL bigint; future HTTP mapping must reject unsafe JS integers or use a lossless revision/ETag representation, rather than silently rounding.

## VERIFIED FACTS — RPCs and publication

| Function                               | Actual contract                                                                                                                                                                                                                                                                                                                                   |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ensure_profile()`                     | Authenticated execute only; derives owner from auth.uid(); transactional inserts, locks existing active profile; idempotent, repairs missing privacy/preferences with private defaults; never initializes from user metadata.                                                                                                                     |
| `app_private.lock_owner()`             | Rejects absent principal, uninitialized/deleting profile; locks profiles row FOR UPDATE. Private helper is not callable by application roles.                                                                                                                                                                                                     |
| `update_own_profile(jsonb,bigint)`     | Whitelists username/displayName/bio; rejects empty/unknown/non-string patches except nullable username; expected profile revision; no owner argument. SQLSTATE 22023 invalid patch, 23514 constraint/public-name failure, 23505 duplicate username, 40001 stale revision, 42501 unavailable owner. Returns void. No trim/lowercase normalization. |
| `set_own_privacy(text,boolean,bigint)` | Expected privacy revision; publishing requires `btrim(display_name) <> ''`; hiding forces discovery false; does not require username. Returns void. Shares profiles-row lock with profile mutation, preventing unsafe interleavings of name clearing and publication.                                                                             |
| `set_own_preferences(...)`             | Existing independent revisioned locale/theme write; not a Phase 3C settings feature.                                                                                                                                                                                                                                                              |
| `get_public_profile(uuid)`             | Exact **UUID** lookup, not username; public + privacy row + no deletion marker; discovery irrelevant. Returns user_id, nullable username, display_name, bio only. Private/missing/deleting/missing-privacy all return zero rows.                                                                                                                  |
| `list_public_profiles(uuid,integer)`   | Same presentation whitelist, public AND discoverable; UUID keyset order; default 20, clamped 1–50. No browser catalog or text search currently exists.                                                                                                                                                                                            |

Mutators are security-definer functions with empty search_path and qualified objects. Public readers are owned by `dance_profile_reader`: NOLOGIN, NOINHERIT, NOBYPASSRLS, restricted column grants and dedicated projection SELECT policies. Application roles cannot assume it. It cannot SELECT avatar_path. Default PUBLIC function execute is revoked; exact/list readers grant anon and authenticated execute. New functions must reproduce this least-privilege pattern.

## VERIFIED FACTS — contracts and application

`packages/contracts/src/identity.ts` exports strict Zod `profilePatchSchema`, `privacySchema`, `preferencesSchema`, `publicProfileSchema` and inferred DTO types. Text limits count Unicode code points. Handles reject uppercase rather than normalize. `PublicProfileDto` contains userId, nullable username, displayName, bio, and **avatarUrl fixed to null**. There is no own-profile result schema, HTTP profile error envelope or revisioned owner write envelope yet. DB rows are not public DTOs.

`apps/web/src/shared/supabase/database.types.ts` is generated persistence typing. `database.ts` corrects generated public RPC username nullability without editing generated output. Extend that correction if a new RETURNS TABLE projection loses nullability too.

`modules/identity/ensureProfile.ts::ensureProfile` verifies `auth.getUser()` before RPC. `authService.ts::{verifiedIdentity,bootstrapAccount}` preserve a session on retryable bootstrap failure. Auth owns this accepted initialization seam; do not move it into Profile merely to match older illustrative diagrams. `app/_infrastructure/supabase.ts` adapts Next cookies. `shared/supabase/server.ts` creates isolated request clients and forces provider fetches to no-store. `refreshSession.ts` verifies getUser, forwards refreshed cookies and protects session-bearing responses from shared caching. Never authorize from getSession or metadata.

`app/_infrastructure/auth.ts` owns exact-origin mutation checks, response cookie/header propagation and safe localized results; these helpers are private today. Its errors use AuthResult/authErrorKey, **not a ready-made Profile API error contract**. Reuse the established pattern through a narrowly justified app adapter helper; do not import app internals into Profile or broaden auth permissions.

`app/[locale]/account/page.tsx` is force-dynamic, verifies identity and displays own email/bootstrap readiness with POST retry. It does not display/edit profile fields. No `modules/profile`, `/u/[username]` page or profile HTTP handlers exist.
