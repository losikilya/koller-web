# [JIRA-TICKET] Короткое название задачи

> Этот файл — входное описание задачи.
> После создания OpenSpec change источником истины становятся его `proposal`, `specs`, `design`, `bdd`, `test-plan` и `tasks`.
> Удалите нерелевантные разделы или укажите `N/A`. Не заполняйте неизвестные данные предположениями.

## Инструкция planning-агенту

1. Прочитать файл полностью до создания OpenSpec artifacts.
2. Проверить описание против существующего кода, действующих OpenSpec specs, ADR и project rules.
3. Считать обязательными только явно сформулированные требования и ограничения.
4. Не превращать предположения и варианты решения в утверждённые требования.
5. Зафиксировать противоречия и неизвестные данные в `Open Questions`.
6. Остановиться и запросить уточнение, если блокирующий вопрос не позволяет составить корректный plan.
7. Для `/change-plan` подготовить artifacts и planning gate, но не начинать implementation.

## Рекомендуемая команда

При вызове команды прикрепите этот заполненный файл через `@ticket.md` в OpenCode composer:

```text
/change-plan Прочитай полностью приложенный @ticket.md.

Используй его как intake-документ задачи.
Проверь описание против существующего кода, OpenSpec, ADR и project rules.
Не додумывай отсутствующие требования и не превращай assumptions в факты.
Блокирующие пробелы вынеси в Open Questions и запроси уточнение.
Создай OpenSpec change и закончи после planning gate без implementation.
```

Для других типов работ используйте соответствующий entry point:

| Тип                                     | Команда                      |
| --------------------------------------- | ---------------------------- |
| Новое или изменённое поведение          | `/change-plan`               |
| Баг с понятным ожидаемым поведением     | `/bugfix` или `/change-plan` |
| Баг с неизвестной причиной              | `/debug`                     |
| Behavior-preserving refactor            | `/refactor`                  |
| Только покрытие существующего поведения | `/test-module`               |
| Read-only аудит долга                   | `/tech-debt-audit`           |
