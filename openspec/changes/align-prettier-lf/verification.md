# Verification

## Root cause and scope

Prettier 2.8.4 required CRLF while HEAD/index tokens.css contained LF (109 lines, 3225 bytes). Windows core.autocrlf=true produced CRLF (3334 bytes), masking the failure. No .editorconfig, previous .gitattributes or core.attributesfile was present. Effective config differed only in EOL from the passing LF check. In an isolated core.autocrlf=false export, the exact focused command failed with exit 1. A broader audit found 233 tracked files with EOL-only failures, including files outside current gates. All 159 failures among the existing root formatting inputs passed after changing only endOfLine to lf; no unrelated style normalization is needed.
